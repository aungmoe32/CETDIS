# CETDIS Project Rules

## What this app is
Campus Event Check-In System (CETDIS). Students RSVP to events. Organizers scan QR codes at the door. Works offline using IndexedDB + background sync.

## Tech Stack Decisions (DO NOT change without user approval)
- **Auth**: Supabase Email OTP (`supabase.auth.signInWithOtp`)
- **Database**: Supabase Postgres via Drizzle ORM (type-safe queries). Direct Supabase client queries only for auth, NOT for data queries.
- **Offline**: IndexedDB via `idb` library + Serwist background sync
- **QR**: `qrcode.react` for display, `html5-qrcode` for camera scanning. NFC is deferred to a future phase.
- **Tests**: Vitest
- **UI**: Clean white theme. Tailwind CSS v4 (already installed). No component library.

## Database Schema Decisions
- `profiles` table (NOT `users`) — `profiles.id` = `auth.users.id` (UUID, mirrors Supabase Auth)
- `events` table — event details, linked to organizer profile
- `tickets` table — bridge table, unique constraint on (user_id, event_id)
- `check_in_token` is a UUID (not a custom slug format)
- Auto-generated by DB trigger on `auth.users` INSERT

## Routing / Access Control
- Route groups: `app/(auth)/`, `app/(student)/`, `app/(organizer)/`
- Root `proxy.ts` (NOT `middleware.ts` — deprecated in Next.js 16) enforces auth. Export function must be named `proxy()`.
- Role-based redirects: unauthenticated → `/login`; wrong role → appropriate home.
- Scanner URL: `/scan?event=<event_id>` — event is selected via URL param.

## RLS Policy Rules
- Enable RLS on ALL tables in the `public` schema.
- Never use `auth.role()` — use `TO authenticated` with ownership predicate in USING.
- UPDATE policies must have both USING and WITH CHECK.
- Never use SECURITY DEFINER to bypass permissions.

## Naming Conventions
- Server Actions: `actions.ts` co-located next to the page that uses them
- API Route Handlers: `app/api/<resource>/route.ts`
- Shared logic (pure functions, no framework deps): `lib/<name>.ts`
- DB/Supabase helpers: `utils/db.ts`, `utils/supabase/`
